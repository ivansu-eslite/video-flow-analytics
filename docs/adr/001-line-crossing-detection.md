# ADR-001: 計數線的跨越判定方式

## Status

Accepted（「無限直線」前提已由 [ADR-003](003-finite-line-segment.md) 修正）

下面三個選項都是在「側別由最近段所在的**無限長直線**決定」這個前提下比較的，因此線的
長度當時不影響計數，人走在線兩端之外照樣被算成跨越。ADR-003 在側別翻轉之外加了一道
「軌跡要真的穿過有限線段」的閘門修正這件事。本 ADR 的其餘結論不變——判側別的方式仍是
取最近段、仍用該段的無限直線定號，Schmitt trigger 與「勿改成全域 signed-side」的告誡
都繼續有效。

判定所用的那個點，其**定義**另由 [ADR-009](009-head-based-foot-point.md) 改變：本 ADR
寫成「腳底點 `((x1+x2)/2, y2)`」之處，現在是上游用 head 框推算後寫進
`tracking_results.parquet` 的落腳點欄位（推算不出來才退回框底邊中點）。判定演算法本身
不變。

## Context

`line_counting` 要從追蹤結果算出「有人跨過計數線幾次、往哪個方向」。這件事要決定
兩件：

- 這一格影格裡，人站在線的哪一邊？往哪邊走算「進來」由這個決定。
- 邊怎麼變才算跨過一次？

這兩件不能分開決定，因為「怎麼判斷人站在哪一邊」會直接影響「什麼樣的變化算跨過」。

現場條件有三個：

- 計數線會彎折，門口不一定是直的。常見的是三段圍成 ㄇ 形，把店內圍在中間。
- 一台攝影機可能有好幾個出入口，每個出入口要分開算。
- 人會在門口停留，腳的位置在線附近來回晃。如果每一格都重新看他站在哪一邊，一次
  進場會被算成好幾次進出。

## Options Considered

### Option A：整條線只有一個方向，人換邊就計一次

把整條計數線當成一條邊界，先定義哪一側是店內，人從一側移到另一側就算跨過一次。

Advantages

- 想法直接，整條線只有一個「內」和一個「外」。

Disadvantages

- ㄇ 形的門口會算錯。三段線把場內參考點圍在中間時，沒辦法給三段一致的答案——左邊
  那段的店內在右手邊，右邊那段的店內在左手邊。
- 門口停留的晃動會被逐格算成進出。

### Option B：只看離人最近的那一段線，人換邊就計一次

不看整條線，只看離人最近的那一段，用這一段判斷他在店內側還是店外側；哪一側算店內，
由場內參考點相對這一段的位置決定。

Advantages

- ㄇ 形和其他形狀都判得對，因為判斷的依據就是他實際穿過的那一段。

Disadvantages

- 門口停留的晃動一樣會被逐格算成進出。一個人站在門口講電話，數字會一直跳。

### Option C：只看最近的那一段線，而且要離線夠遠才算換邊（採用）

判斷站在哪一邊的方式同 Option B。另外拿一條寬度 `crossing_band_px` 的帶子蓋在線上：
人還在帶子裡面時，維持他上一次確定的那一邊；走出帶子才確定他換邊了。確定的邊改變，
才算跨過一次。這種「要超過一定幅度才改變狀態」的做法一般稱為 Schmitt trigger。

Advantages

- 有沒有跨過、往哪個方向、要不要濾掉晃動，用同一個規則處理，不必另外再加時間或
  距離的判斷。
- `crossing_band_px` 設成 0 時帶子沒有寬度，行為就退回 Option B。

Disadvantages

- 多一個要調的參數，不同場景、不同解析度的合適值不一樣。
- 貼著線走過去的人，如果離線的距離一直沒超過帶子寬度，不會被算到。

## Decision

用 Option C。

ㄇ 形是門口計數線常見的形狀，Option A 在這種形狀上方向會判反，先排除。Option B
判得對，但門口停留會讓同一個人被算成好幾次進出，而門口正是計數線最主要的使用場合，
這樣的數字沒辦法用。多一個參數要調，換來可以直接使用的數字，這筆划算。

`crossing_band_px` 設 0 時保留 Option B 的行為，不需要濾晃動的場合（例如用合成資料
驗證）可以關掉。

另外定一條：track 一開始就在某一邊，不算跨過一次，只有換邊才算。這一點和
`zone_mapping` 相反，`zone_mapping` 是人第一次出現在區域裡就算一次 entry。兩邊不
一樣是刻意的——區域佔用問的是「人在不在裡面」，計數線問的是「人有沒有走過去」。

## Consequences

Positive

- ㄇ 形、直線、外凸的門口都判得對，涵蓋實際會拉的線。
- 濾掉晃動的強度只由一個參數控制。
- 計算是整批做完的，不用一條 track 一條 track 跑迴圈。

Negative

- 線往內凹的地方（凹角朝著場內參考點），方向有機會判反：人走到那附近時，離他最近的
  線段會換成另一段，兩段給的答案可能不一致。門口的直線和外凸形狀不會遇到這個情況，
  所以接受這個限制，不改回 Option A。
- 判斷站在哪一邊的程式不能改成「整條線只有一個方向」——改了 ㄇ 形門口就會算錯，也
  就是 Option A 的問題。`services/stats.py` 的 `signed_distance_to_polyline` 和 README
  的「已知限制」都寫了這件事，要改之前先看。
- `crossing_band_px` 要依場景和解析度調。調太小濾不掉停留的晃動，調太大會漏掉貼著線
  走過去的人。
- 掉影格掉得很嚴重時，腳的位置一次跳很遠，可能被誤判成跨過線。一般程度的掉影格仍會
  正確算成一次。
